# Social cards

Thirteen cards at 1200 by 630, one per route, in Datum: paper field, a datum tick at the origin of a hairline, mono overline, serif title, mono data plate. One accent moment per card, which is the tick.

Generated by `generate-og.py`. Content is not hardcoded prose invented for the cards; every overline, title, and year was read off the live site so a card cannot drift from the page it represents.

## Regenerate before publishing

**The PNGs in this directory are rendered in the wrong typeface.** The machine that produced them had no IBM Plex and no registry access, so the rasteriser fell back to DejaVu Serif Bold, which is heavier and more slab-like than IBM Plex Serif. Composition, colour, spacing, and copy are correct; the face is not.

The `.svg` files are the authoritative masters, because they carry the real font stack rather than a rasterised fallback.

### Recommended: no Python

The SVG masters are committed, so day to day you only need to rasterise them. `scripts/render-og.mjs` does that with explicit font files rather than through fontconfig, which matters because `fc-match` substitutes a lookalike silently. That silence is exactly how the first batch shipped in DejaVu Serif with nothing failing.

```bash
pnpm add -D @resvg/resvg-js @ibm/plex
node scripts/render-og.mjs
```

It resolves fonts in this order: `$PLEX_FONT_DIR`, then any `IBMPlex*.ttf` or `.otf` under `node_modules`, then system fonts with a warning. It prints which source it used, so a substitution announces itself.

If librsvg is already installed, this needs no dependency at all, though it relies on system fonts and will not warn about a substitution:

```bash
for f in public/images/og/*.svg; do rsvg-convert -w 1200 -h 630 "$f" -o "${f%.svg}.png"; done
```

### Python path, for changing card content

`generate-og.py` owns content and layout, because it measures text to wrap titles and step the type size. You need it only to add or reword a card, and it requires Pillow:

```bash
sudo apt install python3-pil                    # Debian, Ubuntu, WSL
pip install --break-system-packages Pillow      # if pip refuses under PEP 668
python3 generate-og.py
```

It writes to `public/images/og/` regardless of where it is invoked from, resolved by walking up for `package.json`. An earlier version wrote to the current working directory, which scattered PNGs beside application code when run from `src/lib/`.

Both scripts belong in `scripts/`, not `src/lib/`. Per `REPO_LAYOUT.md`, `src/` is application code, and a build script that is never imported does not belong there.

## Wiring them up

`cookbook-final-pass.md` § 2.2 has the metadata. The short version: `openGraph.images` and `twitter.images` in the root layout point at `/images/og/default.png`, and each project overrides it through `generateMetadata` reading an `ogImage` frontmatter field, which has to be added to `projectSchema` first because Zod strips unknown keys.

```yaml
# content/projects/plane-scraper.mdx
ogImage: /images/og/plane-scraper.png
```

**Do not also add an `opengraph-image.tsx` file** for a route that already declares a static image. Next's file convention emits its own `og:image` tag, so a route carrying both produces two competing tags.

## Verify after deploying

Checked here at 552px, the width LinkedIn renders in a feed: overline, title, and plate all hold. Still worth confirming against the live URLs, because every platform crops and caches differently:

- LinkedIn Post Inspector, which caches aggressively, so inspect before sharing widely
- Facebook Sharing Debugger
- A Slack or Discord paste
- An X draft

`/projects/aircraft` and `/projects/photography` are marked `in progress` on their cards, matching the status on the pages themselves. That is deliberate: a card claiming finished work that the page then contradicts is worse than no card.
