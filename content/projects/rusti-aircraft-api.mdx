A learning project built with Rocket, Diesel, and PostgreSQL. The main implementation detail is the connection pool exposed through Rocket's request-guard system.

## What it actually does

The service uses pre-async Rocket with Diesel over PostgreSQL. `airplanes.rs` defines a Diesel model that derives `Queryable`, `Insertable`, `AsChangeset`, and serde traits. The Diesel query builder implements list, create, read by ID, update, and delete operations.

`pg_pool.rs` wraps an r2d2 connection pool and exposes it through `FromRequest`. A handler declares the pooled connection in its signature, and Rocket acquires and releases it for the request. When the pool is exhausted, the guard returns `ServiceUnavailable` instead of waiting indefinitely. A `Deref` implementation exposes the underlying connection to Diesel call sites.

## Decisions worth defending

| Decision | Reasoning |
|---|---|
| Expose the pool as a request guard | Database access appears in the handler signature, and the framework manages acquisition and release. |
| Return `ServiceUnavailable` on pool exhaustion | A 503 response bounds the failure instead of allowing an exhausted pool to create unbounded request latency. |
| Implement `Deref` for the wrapper | Diesel calls can use the pooled connection without repeated wrapper access. |

## Honest limits

**Authentication does not work and is not claimed.** `auth.rs` contains bcrypt registration and login code with tests, but the entire module is commented out.

The project predates async Rocket. Its scope is one CRUD resource and a small test module, and it has not run under production load.
